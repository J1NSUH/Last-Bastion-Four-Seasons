# Prototype Backlog

이 문서는 첫 프로토타입을 만들기 위한 작업 백로그입니다.

작업은 기능 단위로 쪼개며, 각 항목은 완료 조건을 가집니다.

## 작업 우선순위

우선순위는 다음 기준을 따릅니다.

1. 핵심 재미를 검증하는가?
2. 다른 시스템의 기반이 되는가?
3. 테스트에서 바로 관찰 가능한가?
4. 임시 리소스로도 구현 가능한가?

## 범위 고정

프로토타입 단계에서 MVP는 30일 런을 뜻합니다.

10일 테스트 런은 MVP가 아니라, MVP로 확장해도 되는지 확인하는 관문입니다.

작업을 추가할 때는 먼저 아래 중 어디에 속하는지 표시합니다.

| 범위 | 허용 작업 | 금지 작업 |
| --- | --- | --- |
| M0 | 경로, 구조물, 파괴, 활성 방향, 기본 스폰 | 직업 카드 풀, 상점, 보스 |
| M1 | 1~10일, 기본 카드, 처치 자원, 겹치기, 압축 정산, 첫 보스 | 보스 추가, 계절 규칙, 장기 메타 |
| M2 | 1~30일, 4직업, 보상 카드, 상점, 카드 제거/강화, 아티팩트 | 100일 풀런, 대형 콘텐츠 확장 |

범위 밖 아이디어는 삭제하지 않고 P2 이후 후보로 보냅니다.

## 개발 전환 컷라인

지금부터 새 작업은 상세 기획 항목이 아니라, 바로 만들고 확인할 수 있는 기능 단위로만 추가합니다.

작업을 추가하기 전 아래 4가지를 먼저 확인합니다.

1. 플레이어가 직접 보는 화면 또는 행동이 있는가?
2. 저장해야 하는 상태가 1~3개로 설명되는가?
3. 임시 그래픽과 디버그 UI로도 테스트할 수 있는가?
4. 실패했을 때 고칠 위치가 명확한가?

아래 항목은 M2 완료 전까지 새 P0/P1 작업으로 늘리지 않습니다.

| 보류 묶음 | 이유 |
| --- | --- |
| 31~100일 세부 웨이브 구현 | 30일 MVP 재미가 먼저 확인되어야 합니다. |
| 카드/아티팩트 후보 대량 추가 | 덱 빌딩보다 콘텐츠 양 검수가 먼저 와버립니다. |
| 정교한 메타 진행, 도감, 연대기 | 핵심 전투 루프 검증 뒤에 붙여도 늦지 않습니다. |
| 최종 UI 스킨과 고급 연출 | 임시 리소스로 조작과 가독성을 먼저 봅니다. |
| 세밀한 난이도 곡선 | 첫 구현에서는 시작값과 디버그 조절로 충분합니다. |

기존 상세 문서는 삭제하지 않습니다.

다만 구현 중에는 상세 태그보다 `RunState`, 경로, 구조물, 카드 사용, 웨이브 종료, 보상 정산처럼 실제로 움직이는 상태를 우선합니다.

### P0-000C 구현 컷라인 스냅샷

설명:

첫 개발 착수 시 무엇을 만들고 무엇을 미룰지 한 번에 확인하는 스냅샷입니다.

완료 조건:

- M0는 맵, 기지, 활성 방향, 적 이동, 구조물 배치, 구조물 파괴, 경로 재계산까지만 성공하면 통과입니다.
- M1은 10일 흐름, 기본 카드, 처치 자원, 웨이브 겹치기, 첫 보스가 한 번 이어지면 통과입니다.
- M2는 30일 런, 4직업 시작 덱, 보상, 상점, 카드 제거/강화, 아티팩트가 한 판 안에서 이어지면 통과입니다.
- 31일 이후 계절 규칙, 장기 메타, 도감/훈련장, 파티 연대기는 M2 통과 전 구현 범위가 아닙니다.
- 세부 수치가 미정이어도 디버그 패널에서 적 수, 구조물 체력, 마나 지급량, 웨이브 간격을 조절할 수 있으면 임시 통과로 봅니다.
- 기획 문서의 세부 태그가 아직 구현되지 않아도 핵심 루프가 플레이 가능하면 개발을 멈추지 않습니다.

### P0-000D 코드 프로젝트 착수 결정

설명:

문서 기획에서 실제 게임 프로젝트로 넘어가기 전에, 첫 빌드가 M0 전투 테스트에 집중하도록 범위를 고정합니다.

완료 조건:

- 사용할 엔진이나 프레임워크를 하나 고릅니다.
- 선택 이유는 타일 맵, 타일 클릭 배치, 경로 탐색 제어, 디버그 UI, 데이터 교체 중 3개 이상으로 설명됩니다.
- 첫 실행 화면은 M0 전투 테스트 화면입니다.
- 첫 데이터는 맵 1개, 적 1종, 구조물 2종, 웨이브 1개로 제한합니다.
- 첫 UI는 경로선, 체력 표시, 활성 방향 표시, 디버그 로그만 포함합니다.
- 카드 풀, 상점, 보스, 아티팩트, 저장, 온라인 멀티는 첫 코드 프로젝트 범위에서 제외합니다.
- `P0-000E`부터 `P0-000S`까지로 착수 기준을 잠근 뒤, 프로젝트가 생성되면 `P0-001`부터 `P0-007F`까지를 우선 구현 큐로 둡니다.

### P0-000E 첫 주 구현 목표

설명:

첫 주는 M0 전투 테스트 화면을 열고, 한 웨이브가 기지 피해 또는 웨이브 종료까지 이어지는지만 확인합니다.

완료 조건:

- 실행하면 M0 전투 테스트 화면으로 바로 들어갑니다.
- 21x21 테스트 맵과 중앙 기지가 보입니다.
- 플레이어 수를 임시 값으로 바꾸면 활성 방향 표시가 달라집니다.
- 적 1종이 활성 입구에서 기지로 이동합니다.
- 타워 1종과 바리케이드 1종을 놓을 수 있습니다.
- 바리케이드가 경로에 영향을 주고, 완전 길막은 거부됩니다.
- 구조물 파괴, 기지 피해, 웨이브 종료 중 최소 2개 로그가 보입니다.
- 카드, 상점, 보스, 아티팩트, 저장은 구현하지 않아도 됩니다.

### P0-000F M0 임시 화면과 조작

설명:

첫 구현 화면은 정식 HUD가 아니라, 경로와 구조물 파괴를 확인하는 테스트 화면입니다.

완료 조건:

- 중앙에 테스트 맵, 중앙 기지, 적, 구조물이 보입니다.
- 상단에 기지 체력과 웨이브 진행 상태가 보입니다.
- 좌측에서 플레이어 수 임시 값을 바꿀 수 있고, 활성 방향 표시가 갱신됩니다.
- 하단에 타워 배치, 바리케이드 배치, 웨이브 시작, 리셋 버튼이 있습니다.
- 우측에 경로 재계산, 구조물 파괴, 기지 피해, 웨이브 종료 로그가 보입니다.
- 배치 가능/불가가 타일 색으로 구분됩니다.
- 이 화면에는 카드 손패, 상점, 보상, 보스 UI를 넣지 않습니다.

- 저장, 온라인 멀티, 카드 UI, 상점 UI, 보스 연출 구조는 만들지 않아도 됩니다.

- 일반 웨이브에서 기지 체력 0 도달 시 패배 결과로 전환합니다.
- 치명 상태에서는 웨이브 겹치기 투표가 전원 동의로 바뀝니다.
- 첫 보스 기지 도달은 15 피해와 5초 카운트다운 정책을 사용합니다.
- 패배 분석은 마지막 피해를 준 적보다 반복 누수, 경로 연장 부족, 우선 처치 실패 같은 전장 원인을 우선합니다.
- 기지 피해와 회복은 `base_damage_taken`, `base_recovery_purchased`로 기록합니다.

### P0-007C 기지 회복 경제

설명:

기지 회복이 실수를 완전히 지우는 구매가 아니라, 다음 전투를 시도할 시간을 사는 선택으로 작동하게 만듭니다.

완료 조건:

- 작은 상점 기지 회복은 체력 3, 골드 30입니다.
- 보스 후 상점 기지 회복은 체력 5, 골드 45입니다.
- 기지 체력 10 이하에서는 회복 항목에 가격 +20과 위험 문구를 표시합니다.
- 기지 회복은 최대 체력 30을 넘을 수 없습니다.
- 같은 상점 세션에서 기지 회복은 1회만 구매할 수 있습니다.
- MVP에서는 전투 중 즉시 기지 체력 회복을 제공하지 않습니다.
- 연막 장막 같은 일회성 주문은 회복이 아니라 다음 기지 피해 감소로 처리합니다.
- 회복 가격과 회복량은 웨이브 겹치기 횟수, 처치 수, 클리어 시간, 접근성 설정, 솔로 모드로 바뀌지 않습니다.

### P0-007D 기지 도달 경고와 위험 핑

설명:

기지 피해가 억울한 급사처럼 느껴지지 않도록, 도달 전 경고 단계와 플레이어 확정형 위험 핑 후보를 구현합니다.

완료 조건:

- 적이 기지 외곽 경고권에 들어오면 예상 도달 시간, 예상 피해, 실제 활성 방향을 표시합니다.
- 도달 예상 시간에 따라 `notice`, `warning`, `critical` 단계를 승격합니다.
- 기지 치명 경고는 구조물 경고보다 우선하지만, 보스 전용 5초 카운트다운을 숨기지 않습니다.
- 큰 기지 도달 경고는 MVP에서 동시에 1개만 표시합니다.
- 경고를 클릭하면 집중 화력, 둔화/제어, 경로 확인, 수리 요청, 후방 킬존 이전, 후퇴/보류 후보를 상황에 맞게 2~4개 표시합니다.
- 시스템이 펼친 후보는 플레이어가 확정하기 전까지 직접 핑으로 기록하지 않습니다.
- 위험 핑 후보는 카드를 자동 사용하거나 마나를 쓰거나 구조물을 조작하지 않습니다.
- 솔로에서는 기지 위험 핑을 자기 리마인더 문구로 표시하고, 비활성 방향을 후보에 넣지 않습니다.
- 기지 도달 경고는 `base_breach_warning_raised`, `base_breach_warning_resolved`로 기록합니다.
- 경고와 핑 문구에는 보상 증가, 특정 직업 필수, 개인 책임 표현을 쓰지 않습니다.

### P0-007E 패배 분석 카드와 재도전 제안

설명:

패배 결과를 마지막 적이나 개인 책임이 아니라, 반복된 전장 원인과 다음 시도 운영으로 회수합니다.

완료 조건:

- 패배 시 `CombatReport`와 `base_damage_taken`, `combat_warning_raised`, `ping_resolved` 기록을 묶어 가장 설명력이 큰 원인 1개를 고릅니다.
- 패배 분석 카드는 최대 3장만 표시합니다.
- 첫 카드는 뚫린 방향, 구조물 연쇄 붕괴, 놓친 적 역할, 손패 막힘, 보스 패턴, 정보 전달 실패 중 가장 큰 전장 원인을 보여줍니다.
- 보조 카드는 최대 2장까지 표시하고, 하나는 다음 시도 대응 태그로 쓸 수 있습니다.
- 카드 수치는 누수 횟수, 기지 피해량, 구조물 생존 시간처럼 원인을 설명하는 값만 보여줍니다.
- 개인 딜량, 처치 수, 실수한 플레이어, 핑 미응답자 이름은 표시하지 않습니다.
- 재도전 제안은 최대 2개이며, 새 런 준비 화면에 참고 메모로만 전달됩니다.
- 재도전 제안은 직업, 시작 덱, 아티팩트, 활성 방향을 자동으로 바꾸지 않습니다.
- 솔로 제안은 실제 활성 방향인 동쪽 전선 안의 경로/적 역할/구조물 판단으로만 작성합니다.
- 겹치기 관련 원인은 보상 손해가 아니라 위험 급증과 보류 판단으로 설명합니다.
- `defeat_analysis_card_presented`, `next_run_suggestion_presented`를 기록합니다.

### P0-007F M0 첫 플레이 루프 통합 검증

설명:

M0의 목표는 많은 콘텐츠가 아니라, 한 웨이브에서 경로, 구조물, 파괴, 기지 피해가 끊기지 않고 이어지는지 확인하는 것입니다.

완료 조건:

- 1웨이브 테스트 모드에서 맵, 기지, 활성 방향, 적 스폰, 구조물 배치가 한 화면에 보입니다.
- 적은 활성 방향에서만 등장하고 기지까지 이동합니다.
- 타워 또는 바리케이드 1종 이상을 배치할 수 있습니다.
- 배치 후 적 경로가 다시 계산됩니다.
- 완전 길막은 배치 전 거부됩니다.
- 구조물이 피해를 받고 파괴됩니다.
- 구조물 파괴 후 적 경로가 다시 이어집니다.
- 적이 기지에 도달하면 기지 피해가 적용됩니다.
- 웨이브 종료, 기지 피해, 구조물 파괴 중 최소 2개 이벤트가 디버그 로그에 남습니다.
- 같은 빌드를 3회 연속 실행해도 빈 화면, 멈춤, 경로 끊김이 없습니다.
- 1~4인 임시 값을 바꿔도 비활성 방향에서는 적이 등장하지 않습니다.
- 플레이어가 화면과 로그만 보고 실패 원인을 짧게 설명할 수 있습니다.
- 이 항목을 통과하면 M0 기능을 더 늘리지 않고 카드/마나 최소 루프로 넘어갑니다.
- 카드, 상점, 보스, 아티팩트가 없어도 이 항목은 통과할 수 있습니다.

### P0-007G 카드/마나 최소 루프 착수선

설명:

M0의 디버그 배치 버튼을 카드와 마나 입력으로 바꾸는 첫 연결 작업입니다.

완료 조건:

- 손패가 화면 하단에 보입니다.
- 시드 마나가 웨이브 시작 전에 지급됩니다.
- 타워/바리케이드 배치가 카드 사용으로 실행됩니다.
- 카드 사용은 기존 `BuildStructureCommand`를 호출합니다.
- 마나 부족, 대상 없음, 완전 길막은 카드 사용 전에 거절됩니다.
- 적 처치 시 마나 또는 드로우 게이지 변화가 보입니다.
- 직업별 카드 풀, 보상, 희귀도, 강화, 상점, 아티팩트는 이 항목에 포함하지 않습니다.

### P0-007H M0 첫 내부 테스트

설명:

M0 빌드가 핵심 루프를 눈으로 이해시킬 수 있는지 짧게 확인합니다.

완료 조건:

- 테스트는 1웨이브를 3회 이하로 반복합니다.
- 적의 활성 방향을 바로 알아볼 수 있는지 확인합니다.
- 구조물 배치 후 경로 변화가 눈에 보이는지 확인합니다.
- 구조물 파괴가 전술적 시간 벌기로 보이는지 확인합니다.
- 실패 시 화면과 로그만 보고 원인을 설명할 수 있는지 확인합니다.
- 이 테스트에서는 카드 풀, 보상, 희귀도, 상점, 보스, 아티팩트를 평가하지 않습니다.
- 수정 우선순위는 빈 화면, 경로 끊김, 조작 혼란, 비활성 방향 스폰입니다.

### P0-007I M0 기획 동결과 아이디어 보관

설명:

M0 개발 중 새 아이디어가 나와도 첫 루프 완료 전에는 범위를 넓히지 않습니다.

- 새 적, 새 카드, 보상, 상점, 보스, 아티팩트, 계절 규칙은 보류 아이디어로 기록만 합니다.
- M0 완료 판정 전에는 보류 아이디어를 구현 큐로 올리지 않습니다.

### P1-014 알파 직업 커버리지 러너

알파 테스트 전에 4개 직업의 기본 기믹과 핵심 카드가 깨지지 않았는지 자동 스모크 테스트로 확인합니다.

- 각 직업은 시작 손패 1개와 핵심 카드 손패 1개를 가집니다.
- 수호자는 도발, 피격 유도, 반사 또는 방어 로그를 남깁니다.
- 건축가는 경로 변경, 완전 길막 거절, 바리케이드 파괴 또는 잔해 로그를 남깁니다.
- 원소술사는 광역 피해와 둔화/넉백/빙결 중 1개를 남깁니다.
- 땜장이는 오라 적용과 수리 또는 증폭 로그를 남깁니다.
- 대상 조건이 맞는 카드는 사용 가능해야 하고, 조건이 맞지 않는 카드는 이유 로그를 남겨야 합니다.
- 러너는 승패, 재미, 정답 빌드, 수치 밸런스를 판정하지 않습니다.
- 러너 실패는 알파 테스트 전 필수 수정으로 분류합니다.

완료 조건:

- 공용 카드 강화는 안정 강화 중심 4종만 MVP에서 먼저 검증합니다.
- 모든 대표 강화 옵션은 `CardUpgradeOption` 데이터와 `effectDelta`, `decisionQuestionKo`, `forbiddenPatterns`를 가집니다.
- 특화 강화는 새 조건이나 대가를 하나 이상 가집니다.

- 공용 카드 강화는 직업 고유 역할을 같은 강도로 대체하지 않습니다.
- 강화 옵션은 웨이브 겹치기 보상, 카드 후보 수, 희귀도, 처치 보상 총량을 바꾸지 않습니다.

### P0-015F-2 강화 상점 가격과 추천 규칙

설명:

카드 강화가 파티 골드 경제 안에서 카드 제거, 새 카드 구매, 기지 회복, 구조물 보강과 경쟁하도록 가격 밴드와 추천 후보 생성 규칙을 만듭니다.

완료 조건:

- `shop_upgrade_price_bands_mvp`가 첫 안정 강화, 안정 강화, 특화 강화, 전환 강화, 저주 안정화, 영웅 확정 조율, 마지막 보완 강화 가격을 정의합니다.
- 5일 첫 상점은 일반 카드 안정 강화 1개를 골드 25 기준으로 보여주며, 구매하지 않는 선택을 허용합니다.
- 강화 후보는 최근 사용 카드, 손패에 잡혔지만 쓰지 못한 카드, 피해 진단 태그, 다음 3~5일 압박 태그를 기준으로 생성합니다.
- 추천 강화는 1개만 강조하고, 다른 후보는 최대 2개만 보여줍니다.
- 추천 강화와 같은 문제를 푸는 카드 제거, 기지 회복, 구조물 보강, 일회성 주문 중 최소 1개를 대안으로 표시합니다.
- 같은 플레이어 연속 강화, 파티 최저 강화 수보다 2개 이상 앞선 플레이어, 같은 상점 두 번째 파티 골드 강화, 같은 진단 반복 해결에는 할증이 붙습니다.
- 한 강화 제안의 할증은 최대 +25입니다.
- 강화 추천과 가격은 웨이브 겹치기 횟수, 클리어 시간, 처치 수, 비활성 방향 압박, 숨겨진 승률 예측을 사용하지 않습니다.
- 자동 구매는 없고, 시간 초과 기본 행동은 구매 거절입니다.
- `CardUpgradeShopOffer`와 `shop_purchase`가 최종 가격, 할증 이유, 추천 근거, 대안 항목을 기록합니다.

- 카드 무효 사용은 범위 밖, 대상 조건 불충족, 길막 위험, 보스 정책 중 하나의 이유 태그를 표시합니다.

### P0-015G-2 MVP 카드 예산 배정 감사 구현

설명:

- `budget_cost1_risky_focus`는 MVP에서 명시 계약/저주 카드만 사용할 수 있고 `stat_budget_curse`로 검수합니다.

- 예산 기본 상한을 넘은 카드에는 `exceededAxisTags`, `requiredPolicyIds`, `compensationTagsApplied`가 모두 남습니다.
- 솔로 플레이, 웨이브 겹치기, 빠른 클리어, 처치 수로 `soloBudgetRelaxed`나 `waveStackBudgetRelaxed`가 true가 되면 빌드를 실패시킵니다.
- `MvpCardBudgetAssignmentAudit`과 `card_stat_budget_lock_checked`를 함께 조회해 누락된 예산 배정을 확인합니다.
