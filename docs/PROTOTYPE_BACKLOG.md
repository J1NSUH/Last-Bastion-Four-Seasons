# Prototype Backlog

이 문서는 첫 프로토타입을 만들기 위한 작업 백로그입니다.

작업은 기능 단위로 쪼개며, 각 항목은 완료 조건을 가집니다.

## 작업 우선순위

우선순위는 다음 기준을 따릅니다.

1. 핵심 재미를 검증하는가?
2. 다른 시스템의 기반이 되는가?
3. 테스트에서 바로 관찰 가능한가?
4. 임시 리소스로도 구현 가능한가?

## 범위 고정

프로토타입 단계에서 MVP는 30일 런을 뜻합니다.

10일 테스트 런은 MVP가 아니라, MVP로 확장해도 되는지 확인하는 관문입니다.

작업을 추가할 때는 먼저 아래 중 어디에 속하는지 표시합니다.

| 범위 | 허용 작업 | 금지 작업 |
| --- | --- | --- |
| M0 | 경로, 구조물, 파괴, 활성 방향, 기본 스폰 | 직업 카드 풀, 상점, 보스 |
| M1 | 1~10일, 기본 카드, 처치 자원, 겹치기, 압축 정산, 첫 보스 | 보스 추가, 계절 규칙, 장기 메타 |
| M2 | 1~30일, 4직업, 보상 카드, 상점, 카드 제거/강화, 아티팩트 | 100일 풀런, 대형 콘텐츠 확장 |

범위 밖 아이디어는 삭제하지 않고 P2 이후 후보로 보냅니다.

- 첫 적 접촉 시점을 기록합니다.
- 첫 구조물 피격 시점과 첫 구조물 파괴 시점을 기록합니다.
- 첫 기지 피해 시점을 기록합니다.
- 구조물 종류별 평균 생존 시간을 기록합니다.
- 바리케이드 배치로 늘어난 경로 시간을 기록합니다.
- 플레이어별 마나 획득, 드로우 발동, 손패 막힘 시간을 기록합니다.
- 웨이브 종료 후 기준 범위보다 빠름, 적정, 늦음 상태를 표시합니다.
- 디버그 표시는 밸런스 보정만 돕고, 실제 보상, 적 수, 카드 후보를 자동으로 바꾸지 않습니다.

### P0-007B 기지 체력, 피해, 패배 처리

설명:

기지 체력 30을 기준으로 안정, 위험, 치명, 붕괴 상태를 처리하고, 적 기지 도달 피해와 패배 분석을 구현합니다.

완료 조건:

- `base_health_rule_mvp_001`을 읽어 기지 최대 체력 30, 위험 10~20, 치명 1~9, 붕괴 0 기준을 적용합니다.
- 적이 기지 외곽 경고권에 들어오면 방향, 도달 예상 시간, 예상 피해를 표시합니다.
- 적이 기지 타일에 도달하면 `EnemyData.baseDamage`만큼 기지 피해를 적용합니다.
- 0.75초 안에 여러 적이 도달하면 UI에서는 누수 묶음으로 표시하지만, 실제 피해는 합산합니다.
- 일반 웨이브에서 기지 체력 0 도달 시 패배 결과로 전환합니다.
- 치명 상태에서는 웨이브 겹치기 투표가 전원 동의로 바뀝니다.
- 첫 보스 기지 도달은 15 피해와 5초 카운트다운 정책을 사용합니다.
- 패배 분석은 마지막 피해를 준 적보다 반복 누수, 경로 연장 부족, 우선 처치 실패 같은 전장 원인을 우선합니다.
- 기지 피해와 회복은 `base_damage_taken`, `base_recovery_purchased`로 기록합니다.

### P0-007C 기지 회복 경제

설명:

기지 회복이 실수를 완전히 지우는 구매가 아니라, 다음 전투를 시도할 시간을 사는 선택으로 작동하게 만듭니다.

완료 조건:

- 작은 상점 기지 회복은 체력 3, 골드 30입니다.
- 보스 후 상점 기지 회복은 체력 5, 골드 45입니다.
- 기지 체력 10 이하에서는 회복 항목에 가격 +20과 위험 문구를 표시합니다.
- 기지 회복은 최대 체력 30을 넘을 수 없습니다.
- 같은 상점 세션에서 기지 회복은 1회만 구매할 수 있습니다.
- MVP에서는 전투 중 즉시 기지 체력 회복을 제공하지 않습니다.
- 연막 장막 같은 일회성 주문은 회복이 아니라 다음 기지 피해 감소로 처리합니다.
- 회복 가격과 회복량은 웨이브 겹치기 횟수, 처치 수, 클리어 시간, 접근성 설정, 솔로 모드로 바뀌지 않습니다.

### P0-007D 기지 도달 경고와 위험 핑

설명:

기지 피해가 억울한 급사처럼 느껴지지 않도록, 도달 전 경고 단계와 플레이어 확정형 위험 핑 후보를 구현합니다.

완료 조건:

- 적이 기지 외곽 경고권에 들어오면 예상 도달 시간, 예상 피해, 실제 활성 방향을 표시합니다.
- 도달 예상 시간에 따라 `notice`, `warning`, `critical` 단계를 승격합니다.
- 기지 치명 경고는 구조물 경고보다 우선하지만, 보스 전용 5초 카운트다운을 숨기지 않습니다.
- 큰 기지 도달 경고는 MVP에서 동시에 1개만 표시합니다.
- 경고를 클릭하면 집중 화력, 둔화/제어, 경로 확인, 수리 요청, 후방 킬존 이전, 후퇴/보류 후보를 상황에 맞게 2~4개 표시합니다.
- 시스템이 펼친 후보는 플레이어가 확정하기 전까지 직접 핑으로 기록하지 않습니다.
- 위험 핑 후보는 카드를 자동 사용하거나 마나를 쓰거나 구조물을 조작하지 않습니다.
- 솔로에서는 기지 위험 핑을 자기 리마인더 문구로 표시하고, 비활성 방향을 후보에 넣지 않습니다.
- 기지 도달 경고는 `base_breach_warning_raised`, `base_breach_warning_resolved`로 기록합니다.
- 경고와 핑 문구에는 보상 증가, 특정 직업 필수, 개인 책임 표현을 쓰지 않습니다.

### P0-007E 패배 분석 카드와 재도전 제안

설명:

패배 결과를 마지막 적이나 개인 책임이 아니라, 반복된 전장 원인과 다음 시도 운영으로 회수합니다.

완료 조건:

- 패배 시 `CombatReport`와 `base_damage_taken`, `combat_warning_raised`, `ping_resolved` 기록을 묶어 가장 설명력이 큰 원인 1개를 고릅니다.
- 패배 분석 카드는 최대 3장만 표시합니다.
- 첫 카드는 뚫린 방향, 구조물 연쇄 붕괴, 놓친 적 역할, 손패 막힘, 보스 패턴, 정보 전달 실패 중 가장 큰 전장 원인을 보여줍니다.
- 보조 카드는 최대 2장까지 표시하고, 하나는 다음 시도 대응 태그로 쓸 수 있습니다.
- 카드 수치는 누수 횟수, 기지 피해량, 구조물 생존 시간처럼 원인을 설명하는 값만 보여줍니다.
- 개인 딜량, 처치 수, 실수한 플레이어, 핑 미응답자 이름은 표시하지 않습니다.
- 재도전 제안은 최대 2개이며, 새 런 준비 화면에 참고 메모로만 전달됩니다.
- 재도전 제안은 직업, 시작 덱, 아티팩트, 활성 방향을 자동으로 바꾸지 않습니다.
- 솔로 제안은 실제 활성 방향인 동쪽 전선 안의 경로/적 역할/구조물 판단으로만 작성합니다.
- 겹치기 관련 원인은 보상 손해가 아니라 위험 급증과 보류 판단으로 설명합니다.
- `defeat_analysis_card_presented`, `next_run_suggestion_presented`를 기록합니다.

## Epic 4: 웨이브

### P0-013 WaveSpawnPlan 생성

설명:

원본 웨이브 데이터와 RunState를 조합해 실제 전투용 스폰 계획을 만듭니다.

완료 조건:

- 원본 웨이브의 `preferredDirections`를 읽습니다.
- `activeDirections` 밖의 방향은 실제 `directions`에 들어가지 않습니다.

- 웨이브 겹치기 튜토리얼은 보상 증가 문구를 사용하지 않습니다.

### P1-009B 첫 10일 회수 문구와 훈련장 연결

설명:

첫 10일의 웨이브, 리포트, 보상 이유, 패배 카드가 같은 학습 태그를 회수하고, 필요할 때만 도감/훈련장 재방문으로 이어지게 구현합니다.

완료 조건:

- `FirstSessionCopyTrainingBridge` 데이터를 읽어 일자별 회수 문구와 재방문 제안을 연결합니다.
- `ui.first_session.*`와 `ui.revisit.*` 키가 한국어/영어 현지화에 존재합니다.
- 각 첫 10일 재방문 제안은 하루 1회 이하로 표시됩니다.
- 재방문 제안에는 `닫기`가 항상 있습니다.
- `짧게 연습`은 실제 런 덱, 골드, 아티팩트, 기지 체력, 활성 방향을 변경하지 않습니다.
- `메모로 가져가기`는 새 런 준비 메모만 만들고 직업, 카드, 아티팩트, 활성 방향을 자동으로 바꾸지 않습니다.
- 문구는 정답 카드, 필수 직업, 자동 빌드, 보상 증가, 희귀도 증가, 비활성 방향 압박을 암시하지 않습니다.
- 솔로 재방문은 동쪽 외 방향을 실제 방어 대상으로 표시하지 않습니다.
- `onboarding_hint_shown`, `first_session_checkpoint`, `knowledge_revisit_started`, `training_scenario_started`, `training_scenario_completed`를 연결 기록으로 확인할 수 있습니다.

### P1-010A 플레이테스트 대시보드

설명:

원본 텔레메트리를 기획 질문별 패널로 집계해, 다음 빌드에서 무엇을 고칠지 결정할 수 있게 만듭니다.

완료 조건:

- `PlaytestDashboardRun`, `PlaytestDashboardPanel`, `PlaytestDerivedMetric` 데이터를 읽어 대시보드를 구성합니다.
- `PlaytestDashboardViewLayout`, `PlaytestDashboardRedFlagRule`, `PlaytestDashboardActionQueueItem` 데이터를 읽습니다.
- `dashboard_run_summary`, `dashboard_pacing`, `dashboard_wave_stack_tempo`, `dashboard_defense_line` 패널을 표시합니다.
- `dashboard_cards_resources`, `dashboard_reward_shop_event`, `dashboard_learning_recall`, `dashboard_copy_guardrail` 패널을 표시합니다.
- 상단 런 스트립, 패널 카드 그리드, 위험 신호 드릴다운, 다음 빌드 액션 큐를 표시합니다.
- 상단 런 스트립에는 `buildId`, `runMode`, `playerCountAtStart`, `activeDirections`, 도달 일자, 총 시간, 기지 피해를 표시합니다.
- 패널 카드는 핵심 수치 1~3개만 먼저 보여주고, 원본 이벤트는 드릴다운에서 펼칩니다.
- 위험 신호는 조건, 연결 이벤트, 관찰자 메모, 가능한 의미, 다음 테스트 가설을 함께 보여줍니다.
- 액션 큐는 `proposed`, `accepted_for_next_build`, `deferred`, `resolved` 상태를 가집니다.
- `activeDirections`와 실제 `directions`를 분리해 표시합니다.
- 솔로 런에서 비활성 방향을 실패 원인이나 추천 보강 대상으로 표시하지 않습니다.
- 웨이브 겹치기 사용량을 보상 효율, 희귀도 효율, 성장 효율로 표시하지 않습니다.
- 개인 딜량 순위, 개인 처치 순위, 개인 실수 목록을 만들지 않습니다.
- 액션 큐는 전투, 보상, 상점, 카드 후보, 희귀도 데이터를 자동으로 바꾸지 않습니다.
- `playtest_dashboard_run_aggregated`, `playtest_dashboard_panel_flagged`, `playtest_observer_note_attached`, `playtest_dashboard_action_queued`를 기록합니다.
