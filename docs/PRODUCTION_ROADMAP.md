# Production Roadmap

이 문서는 **Last Bastion: Four Seasons**를 실제로 만들 때의 제작 순서와 마일스톤 기준을 정리합니다.

README가 게임의 설계 기준이라면, 이 문서는 "무엇을 어떤 순서로 만들 것인가"를 다룹니다.

## 제작 원칙

- 재미 검증이 비주얼 완성보다 우선입니다.
- 경로 탐색, 구조물 파괴, 처치 기반 자원 루프를 가장 먼저 검증합니다.
- 웨이브 겹치기는 보상 시스템이 아니라 템포 시스템으로 구현합니다.
- 첫 보스는 화려한 패턴보다 방어선 재설계를 강제하는 역할에 집중합니다.
- 콘텐츠 양은 핵심 루프가 살아난 뒤 늘립니다.

## 마일스톤 개요

| 단계 | 목표 | 예상 결과물 |
| --- | --- | --- |
| M0 | 핵심 전투 기반 검증 | RunState, 활성 방향, 1개 맵, 기본 적, 구조물 설치/파괴 |
| M1 | 10일 테스트 런 | 첫 보스까지 플레이 가능 |
| M2 | 30일 MVP 런 | 4직업, 카드 보상, 상점, 아티팩트 |
| M3 | 100일 풀런 설계 검증 | 계절, 보스 반복, 장기 운영 |
| M4 | 협동 경험 고도화 | 멀티 투표, 핑, 역할 시너지 |
| M5 | 콘텐츠 확장 | 보스/적/카드/아티팩트 확장 |
| M6 | 출시 후보 | QA, 튜토리얼, 접근성, 밸런스 안정화 |

MVP라는 이름은 M2에만 사용합니다.

M1은 10일 테스트 런이며, M2로 넘어가기 위한 관문입니다.

| 관문 | 통과 질문 | 통과 전 금지 |
| --- | --- | --- |
| M0 -> M1 | 경로와 구조물 파괴가 전투 중 깨지지 않는가? | 카드 풀 확장, 상점, 아티팩트 |
| M1 -> M2 | 첫 10일에서 핵심 루프를 설명할 수 있는가? | 보스 추가, 적 대량 추가, 계절 규칙 |
| M2 -> M3 | 30일 후 다시 플레이하고 싶은가? | 100일 풀런 구현, 장기 메타 성장 |

## M0: 핵심 전투 루프

목표:

런 시작 고정값, 활성 방향, 경로 탐색, 구조물 파괴가 하나의 전투 루프로 이어지는지 확인합니다.

이 단계의 목표는 예쁜 전투가 아니라, 이후 모든 콘텐츠가 올라갈 기반을 검증하는 것입니다.

포함:

- RunState 생성
- 인원수별 activeDirections 확정
- 인원수별 scalingProfileId 확정
- 21x21 기본 맵
- 중앙 3x3 기지
- 북/동/남/서 입구와 활성 방향 표시
- WaveSpawnPlan 생성
- WaveScheduler
- 기본 공격 타워
- 기본 바리케이드
- 회색 행렬
- 기지 체력
- 경로 표시
- 구조물 체력 표시

성공 기준:

- 런 시작 시 playerCountAtStart, activeDirections, scalingProfileId가 고정됩니다.
- 현재 접속 인원이 바뀌어도 활성 방향이 다시 계산되지 않습니다.
- WaveSpawnPlan은 activeDirections 밖의 방향을 포함하지 않습니다.
- EnemySystem은 확정된 WaveSpawnPlan대로만 적을 생성합니다.
- 적이 항상 기지까지 도달 가능한 경로를 찾습니다.
- 플레이어가 바리케이드로 경로를 비틀 수 있습니다.
- 완전 길막 시 명확한 피드백이 나옵니다.
- 구조물이 파괴되면 적이 새 경로를 찾습니다.
- 디버그 패널에서 RunState와 다음 WaveSpawnPlan을 확인할 수 있습니다.

이 단계에서 하지 않는 것:

- 덱 빌딩
- 직업
- 보스
- 상점
- 아티팩트
- 고급 비주얼

M0 통과 조건:

- 1인 런에서는 동쪽에서만 일반 웨이브가 나옵니다.
- 2인 런에서는 북쪽과 동쪽만 일반 웨이브 후보가 됩니다.
- 웨이브 겹치기 없이도 한 웨이브가 시작되고 끝납니다.
- 구조물이 파괴된 뒤에도 경로와 WaveSpawnPlan 상태가 깨지지 않습니다.

## M1: 10일 테스트 런

목표:

첫 보스까지 이어지는 짧은 런에서 핵심 재미가 살아나는지 확인합니다.

M1은 콘텐츠 완성 빌드가 아니라, M2 MVP로 넘어갈 자격을 확인하는 빌드입니다.

포함:

- M0 기반 전체
- 10일 웨이브 테이블
- 1~10일 WaveSpawnPlan 예약
- 회색 행렬, 틈새 주자, 균열 망치
- 기본 카드 사용
- 시드 마나
- 처치 기반 마나와 드로우
- 버리기
- 웨이브 겹치기
- 압축 정산
- 카드 보상
- 침묵의 거상
- wave_started, wave_stack_vote_resolved, wave_stacked, wave_completed 기본 텔레메트리

성공 기준:

- 플레이어가 웨이브 겹치기를 자발적으로 누릅니다.
- 웨이브 겹치기를 누른 이유가 보상이 아니라 기다림 감소입니다.
- 웨이브 겹치기는 예약된 다음 WaveSpawnPlan만 앞당깁니다.
- 비활성 방향이 웨이브 겹치기로 열리지 않습니다.
- 겹친 전투 후 정산이 보상 증가가 아니라 시간 압축으로 읽힙니다.
- 구조물 파괴가 전술로 느껴집니다.
- 첫 보스가 방어선 재설계를 유도합니다.
- 패배 원인을 플레이어가 설명할 수 있습니다.

이 단계의 핵심 질문:

> 구조물 파괴와 경로 재계산이 정말 재미있는가?

이 질문에 답하지 못하면 다음 단계로 넘어가지 않습니다.

## M2: 30일 MVP 런

목표:

4개 직업과 덱 빌딩, 보상, 상점, 아티팩트가 결합된 축소판 로그라이크를 완성합니다.

M2는 이 게임의 첫 진짜 MVP입니다.

포함:

- 인원수별 스케일링 검증
- 4개 직업 시작 덱
- 직업별 보상 카드 풀
- 공용 카드 풀
- 적 5~8종
- 30일 웨이브 테이블
- 상점 가격표
- 카드 제거
- 카드 강화
- 아티팩트 5~10종
- 보스 1종 + 강화형

성공 기준:

- 직업마다 같은 맵을 다르게 풉니다.
- 1~4인 모두 활성 방향과 스케일링이 의도대로 작동합니다.
- 보상 카드 선택이 매번 고민됩니다.
- 카드 제거와 강화가 서로 다른 선택으로 느껴집니다.
- 아티팩트가 파티 운영 방향을 바꿉니다.
- 30일 보스 결과 요약까지 30~45분 안에 끝납니다.
- 30일 런이 끝나면 다른 직업이나 다른 빌드로 다시 해보고 싶어집니다.

M2에서 가장 위험한 실패:

- 1인은 너무 단조롭고 4인은 정보 과부하가 됩니다.
- 원소술사 광역 피해가 모든 문제를 해결합니다.
- 땜장이 수리로 구조물 파괴가 무의미해집니다.
- 웨이브 겹치기가 효율 버튼으로 변합니다.
- 카드 보상 풀이 너무 커져서 덱 방향이 흐려집니다.
- 30일 MVP가 50분을 넘었는데도 난이도 문제로만 오해합니다.

## M3: 100일 풀런

목표:

100일 구조가 피로하지 않고, 웨이브 겹치기와 계절 전환으로 템포가 유지되는지 확인합니다.

포함:

- 100일 진행표
- 4계절 압박
- 10일 단위 보스 반복
- 보스 3~4종
- 계절 전환 보상
- 장기 메타 일부
- 최종 보스 겨울의 문

성공 기준:

- 숙련 파티 기준 75~100분 안에 풀런이 끝납니다.
- 웨이브 겹치기를 쓰면 기다림이 줄지만, 위험 판단은 남습니다.
- 계절이 바뀔 때 방어선 설계가 달라집니다.
- 보스가 반복되어도 피로하지 않습니다.
- 최종 20일에서 긴장감이 유지됩니다.

## M4: 협동 경험 고도화

목표:

여러 명이 같은 화면을 보며 빠르게 판단하는 감각을 강화합니다.

포함:

- 활성 침공 방향 로비 표시
- 핑 시스템
- 웨이브 겹치기 투표 UI
- 아티팩트 선택 투표
- 파티 골드 사용 투표
- 전술 느림 모드
- 플레이어별 마나/손패 표시
- 보스 부위 집중 공격 표시

성공 기준:

- 플레이어가 채팅 없이도 기본 의도를 전달할 수 있습니다.
- 투표가 전투 템포를 과하게 끊지 않습니다.
- 각자 자기 라인만 보는 상황이 줄어듭니다.
- 보스전에서 자연스럽게 집중 공격 대상이 정해집니다.
- 3~4인에서 빠른 라인 지원 요청과 수리 요청이 자연스럽게 발생합니다.

## M5: 콘텐츠 확장

목표:

핵심 루프가 안정된 뒤 반복 플레이를 늘립니다.

확장 순서:

1. 적 변종 추가
2. 직업별 카드 추가
3. 아티팩트 추가
4. 보스 추가
5. 이벤트 추가
6. 계절별 맵 규칙 추가
7. 장기 메타 해금 추가

장기 메타 해금은 `post_run_meta_flow`를 기준으로 추가합니다.

먼저 도감, 보스 기록, 훈련 장면, 외형 보상처럼 밸런스에 직접 영향을 주지 않는 해금을 넣고, 새 카드/아티팩트 풀은 역할 태그와 등장 구간을 정한 뒤 천천히 넓힙니다.

콘텐츠 추가 원칙:

- 새 콘텐츠는 기존 직업 중 최소 2개 이상의 플레이를 다르게 만들어야 합니다.
- 새 적은 단순 체력 증가가 아니라 새로운 대응 질문을 던져야 합니다.
- 새 보스는 기존 시스템 하나를 다른 방식으로 시험해야 합니다.
- 새 아티팩트는 수치 증가보다 운영 방향 변화를 우선합니다.
- 장기 메타는 공격력/체력/보상 배율을 누적시키지 않고 정보와 선택지를 넓히는 방식으로만 확장합니다.

## M6: 출시 후보

목표:

기능, 밸런스, 온보딩, 접근성, 협동 흐름을 안정화합니다.

포함:

- 튜토리얼 완성
- 실패 피드백 화면
- 접근성 옵션
- 저장/재접속
- 주요 버그 수정
- 밸런스 패스
- 사운드/비주얼 폴리싱
- 100일 풀런 QA

출시 후보 기준:

- 신규 플레이어가 10분 안에 기본 루프를 이해합니다.
- 첫 패배 후 다시 시도할 이유를 이해합니다.
- 4인 파티에서 한 사람이 게임을 독점하지 않습니다.
- 웨이브 겹치기가 보상 버튼으로 오해되지 않습니다.
- 보스전이 체력 높은 일반 웨이브처럼 느껴지지 않습니다.

## 리스크 관리

| 리스크 | 징후 | 대응 |
| --- | --- | --- |
| RunState가 늦게 구현됨 | 활성 방향과 스케일링이 각 시스템에서 따로 계산됨 | M0에서 RunState와 ScalingSystem을 먼저 고정 |
| WaveSpawnPlan 없이 스폰함 | EnemySystem이 임의 방향을 선택함 | WaveSpawnPlanner와 WaveScheduler를 선행 구현 |
| 인원수별 방향 규칙이 깨짐 | 1인 런에서 동쪽 외 웨이브 등장 | activeDirections 검증과 디버그 표시 추가 |
| 재접속 때 밸런스가 바뀜 | 접속 인원 변화 후 웨이브 방향/수량이 바뀜 | playerCountAtStart 기준 저장, 현재 접속 인원과 분리 |
| 경로 탐색이 재미보다 스트레스가 됨 | 플레이어가 왜 막히는지 모름 | 경로 미리보기와 불가 피드백 강화 |
| 구조물 파괴가 짜증남 | 플레이어가 설치를 포기 | 파괴 보상, 잔해, 회수 효과 강화 |
| 웨이브 겹치기가 강제됨 | 항상 즉시 누름 | 위험 증가, UI 문구 재검토 |
| 전투가 너무 정신없음 | 패배 원인 설명 불가 | 경고 우선순위와 화면 정리 |
| 덱 빌딩이 흐림 | 카드 선택이 의미 없음 | 카드 풀 축소, 직업 고유 카드 강화 |
| 협동이 약함 | 각자 자기 구역만 봄 | 공유 위기, 보스 부위, 투표 강화 |

## 다음 작업 후보

현재 기획 기준에서 바로 착수할 수 있는 작업입니다.

1. RunState와 인원수별 활성 방향 테이블 구현
2. ScalingSystem과 스케일링 프로필 적용
3. WaveSpawnPlanner와 WaveScheduler 구현
4. M0 맵/경로/구조물 파괴 프로토타입 제작
5. 10일 테스트 런 구현
6. 침묵의 거상 임시 보스 제작
7. 4직업 시작 덱 카드 데이터화
8. 플레이테스트 기록 양식 제작
