# System Rules And Edge Cases

이 문서는 **Last Bastion: Four Seasons**의 시스템 판정 순서와 예외 규칙을 정리합니다.

구현 중 규칙이 충돌할 때 어떤 판정이 우선인지 명확히 하기 위한 문서입니다.

## 판정 우선순위

전투 중 여러 효과가 동시에 발생하면 아래 순서로 처리합니다.

1. 기지 패배 조건 확인
2. 보스 즉시 패배 조건 확인
3. 구조물 설치/파괴로 인한 경로 유효성 확인
4. 적 이동
5. 도발 대상 갱신
6. 구조물 공격
7. 적 공격
8. 카드 즉발 효과
9. 상태이상 갱신
10. 적 사망 처리
11. 처치 기반 자원 지급
12. 구조물 파괴 후 효과
13. 잔해 생성
14. 경로 재계산
15. 웨이브 종료 확인
16. 보상 정산

동시에 일어난 것처럼 보여도 내부 처리는 이 순서를 따릅니다.

## 전투 상태 흐름

하루는 아래 상태를 순서대로 지납니다.

1. 하루 시작
2. 다음 웨이브 예고
3. 시드 마나 지급
4. 준비 입력 허용
5. 전투 시작
6. 전투 입력과 판정 큐 처리
7. 웨이브 종료 확인
8. 보상 정산
9. 상점, 이벤트, 보스 준비 등 전투 사이 처리

상태가 바뀔 때마다 남아 있는 임시 효과의 처리 방식을 명확히 합니다.

| 상태 변화 | 유지 | 제거 |
| --- | --- | --- |
| 준비 -> 전투 | 손패, 마나, 설치 구조물 | 준비 전용 미리보기 |
| 전투 -> 보상 | 덱, 골드, 아티팩트, 기지 피해 | 임시 도발, 전투 전용 버프, 남은 투사체 |
| 보상 -> 다음 하루 | 덱 변경, 카드 강화, 기지 상태 | 사용하지 않은 전투 중 버리기 횟수 |
| 보스 처치 -> 상점 | 보스 아티팩트 후보, 골드 | 보스 전용 압력 타일 |

전투 중 일시정지나 배속은 상태를 바꾸지 않습니다.

## 활성 침공 방향 규칙

런 시작 인원수에 따라 일반 웨이브가 사용할 수 있는 침공 방향을 고정합니다.

| 런 시작 인원수 | 활성 침공 방향 |
| ---: | --- |
| 1명 | 동쪽 |
| 2명 | 북쪽, 동쪽 |
| 3명 | 서쪽, 북쪽, 동쪽 |
| 4명 | 서쪽, 북쪽, 동쪽, 남쪽 |

활성 방향은 로비에서 인원이 확정되고 런을 시작하는 순간 결정됩니다.

런 도중에는 아래 상황이 생겨도 활성 방향을 다시 계산하지 않습니다.

- 플레이어 연결 끊김
- 플레이어 재접속
- 보상 화면에서 장시간 미선택
- 호스트 이전
- 일시정지 또는 배속 변경

비활성 방향은 일반 웨이브 스폰 후보에서 제외됩니다.

웨이브 겹치기는 다음 웨이브를 앞당길 뿐, 비활성 방향을 새로 열지 않습니다.

보스, 이벤트, 아티팩트는 비활성 방향을 연출, 배경 정보, 예고 장식으로 사용할 수 있습니다.

하지만 적 스폰, 필수 방어 압박, 추천 방어 방향으로 열지는 않습니다.

## 새 런 준비 규칙

새 런 준비는 `new_run_setup_loop_6step`을 사용합니다.

처리 순서:

1. 결과/메타/도감에서 넘어온 다음 런 제안을 표시하고 `new_run_setup_started`를 기록합니다.
2. 현재 로비 인원 기준 활성 방향 미리보기를 표시하고 `lobby_active_direction_previewed`를 기록합니다.
3. 런 길이와 난이도를 선택합니다.
4. 각 플레이어가 직업을 선택하고 `class_selection_resolved`를 기록합니다.
5. 파티가 이번 런에서 시험할 운영 한 줄을 확인하고 `party_intent_confirmed`를 기록합니다.
6. 시작 버튼을 누르면 `playerCountAtStart`, `activeDirections`, `scalingProfileId`, `seed`를 확정하고 `run_state_locked`를 기록합니다.

새 런 준비 제한:

- 다음 런 제안은 직업, 카드, 아티팩트, 활성 방향을 자동으로 바꾸지 않습니다.
- 로비에서 인원이 바뀌면 미리보기 방향은 갱신할 수 있지만, 런 시작 후에는 다시 계산하지 않습니다.
- 런 설정 화면에는 웨이브 겹치기 보상 모드, 희귀도 증가 모드, 후보 수 증가 모드를 만들지 않습니다.
- 직업 선택 화면은 필수 직업, 정답 조합, 자동 빌드 문구를 표시하지 않습니다.
- 준비 합의는 투표가 아니라 파티 의도를 맞추는 짧은 확인입니다.

## 입력 큐 규칙

플레이어 입력은 즉시 화면에 반응하되, 실제 규칙 처리는 서버 또는 호스트의 판정 큐에서 확정합니다.

입력 큐 대상:

- 카드 사용
- 구조물 설치
- 구조물 수리
- 버리기
- 웨이브 겹치기 제안
- 핑과 짧은 전술 요청

이미 시작된 적 공격 모션은 같은 프레임의 수리 입력으로 취소하지 않습니다.

다만 피해가 적용되기 전 보호막이나 자동 복구가 큐에 먼저 들어와 있었다면 정상 적용됩니다.

카드 입력이 실패하는 경우:

- 마나 부족
- 대상 사라짐
- 대상이 판정 시점에 유효하지 않음
- 손패에 해당 카드가 없음
- 같은 카드가 이미 처리 중임

실패한 입력은 자원을 쓰지 않고, UI에 짧은 이유를 남깁니다.

## 경로 규칙

기본 원칙:

- 적은 항상 기지로 향하는 경로를 가져야 합니다.
- 플레이어는 경로를 길게 만들 수 있지만 완전히 막을 수 없습니다.
- 구조물 설치 전에는 반드시 경로 유효성을 미리 검사합니다.

### 길막 판정

설치가 거부되는 경우:

- 모든 입구에서 기지까지 경로가 사라집니다.
- 보스 전용 경로 폭 3타일이 완전히 막힙니다.
- 이미 이동 중인 적이 어떤 방향으로도 진행할 수 없습니다.

설치가 허용되는 경우:

- 경로가 길어지지만 남아 있습니다.
- 특정 적만 도발로 구조물을 공격하게 됩니다.
- 임시 구조물이 짧은 시간 후 사라져 경로가 복구됩니다.

경로 판정 결과 코드는 `PATHFINDING_AND_MAZING.md`의 코드명을 따릅니다.

시스템 규칙 문서에서는 이 코드가 다른 판정과 충돌할 때의 우선순위만 다룹니다.

## 도발 규칙

도발은 적의 목표를 바꾸지만, 모든 행동을 무효화하지 않습니다.

도발 우선순위:

1. 강제 패턴 중인 보스
2. 도발 면역 또는 도발 저항 상태의 적
3. 가장 강한 도발 효과
4. 가장 가까운 도발 구조물
5. 기존 기지 경로

여러 도발이 겹치면 가장 가까운 도발 구조물을 우선합니다.

도발 구조물이 파괴되면 즉시 목표를 다시 계산합니다.

## 구조물 생애주기 규칙

구조물은 설치, 압박, 선택, 파괴, 잔해, 재건의 흐름을 가집니다.

이 흐름은 플레이어에게 "계속 살릴 것인가, 전술적으로 버릴 것인가"를 묻기 위한 규칙입니다.

### 6단계 처리

1. 설치 목적 기록

구조물을 설치할 때 `structurePurposeTag`를 기록합니다.

예: `killzone_damage`, `taunt_anchor`, `path_bend`, `aura_core`, `temporary_delay`.

2. 위험 노출

구조물이 파괴형 표식, 과열, 결빙, 보스 압력, 도발 집중 공격을 받으면 위험 태그를 붙입니다.

3. 선택 가능 상태

구조물 체력이 낮거나 위험 태그가 붙으면 수리, 강화, 이전, 의도적 희생, 후방 재건 중 하나를 선택할 수 있어야 합니다.

4. 파괴 판정

체력 0이 되면 파괴 직전, 파괴 순간, 파괴 이후 트리거를 순서대로 확인합니다.

5. 경로 재계산

구조물이 사라지고 잔해가 남은 뒤 경로를 다시 계산합니다.

완전 길막이 생기면 잔해를 약화하거나 가장 오래된 잔해를 `밟힌 잔해`로 바꿉니다.

6. 재건 안내

전투 후 리포트와 예고 UI는 같은 자리 재설치, 후방 재건, 오라 분산, 임시 구조물 중 무엇이 유효했는지 짧게 보여줍니다.

### 살림/버림 선택 기준

| 선택 | 좋은 사용 | 금지선 |
| --- | --- | --- |
| 수리 | 핵심 도발, 오라, 강화 타워를 몇 초 더 버팀 | 모든 파괴형/보스 패턴 무효화 |
| 강화 | 다음 큰 피해를 예고 보고 대비 | 상시 무적 방어선 |
| 이전 | 압력/결빙/표식 밖으로 핵심 구조물 이동 | 경로 판정 우회 |
| 의도적 희생 | 폭발, 잔해, 가시, 딜타임 확보 | 무한 회수 자원 루프 |
| 후방 재건 | 무너진 전선을 뒤로 옮김 | 같은 위치 자동 복구 반복 |

수리와 강화는 구조물을 "살리는" 선택이지만, 전투 전체를 닫는 선택이 되면 안 됩니다.

의도적 희생은 손해를 전술 가치로 바꾸는 선택이지, 공짜 자원을 만드는 선택이 아닙니다.

## 구조물 파괴 규칙

구조물이 체력 0이 되면 즉시 파괴됩니다.

파괴 처리 순서:

1. 파괴 이벤트 발생
2. 파괴 전 발동 효과 확인
3. 파괴 위치 기록
4. 폭발/회수/잔해 효과 처리
5. 구조물 제거
6. 경로 재계산

자동 복구 효과가 있으면 구조물 제거 전에 발동합니다.

자동 복구가 발동하면 파괴 이벤트는 기록하지만, 구조물은 낮은 체력으로 유지됩니다.

### 파괴 트리거 구분

구조물 파괴와 관련된 효과는 아래 세 종류로 나눕니다.

| 트리거 | 발동 시점 | 예시 |
| --- | --- | --- |
| 파괴 직전 | 체력 0 판정 직후, 제거 전 | 자동 복구, 최후 보호막 |
| 파괴 순간 | 구조물이 실제로 제거될 때 | 폭발, 잔해 생성, 주변 둔화 |
| 파괴 이후 | 경로 재계산 이후 | 회수 보상, 다음 설치 비용 감소 |

자동 복구가 구조물을 살렸다면 `파괴 직전` 효과만 발동하고, `파괴 순간` 효과는 발동하지 않습니다.

단, 카드 설명에 "파괴될 뻔할 때"라고 적힌 효과는 자동 복구와 함께 발동할 수 있습니다.

파괴 보상은 구조물을 일부러 무한히 부수는 자원 루프가 되면 안 됩니다.

같은 구조물에서 10초 안에 두 번 이상 회수 계열 보상이 발생하면 두 번째부터 보상을 줄이거나 막습니다.

### 재건 제한

재건은 무너진 방어선을 다시 설계하게 만드는 장치입니다.

같은 구조물을 같은 위치에 즉시 반복 재건하는 것은 기본적으로 제한합니다.

재건 규칙:

- 자동 복구는 같은 구조물당 한 웨이브에 1회만 기본 허용합니다.
- 같은 타일에 같은 구조물을 5초 안에 다시 세우면 최대 체력이나 지속 시간이 낮아질 수 있습니다.
- 보스 압력, 결빙, 과열 같은 위험 권역 안에서는 재건 미리보기에 효율 감소를 표시합니다.
- 전투 후 재건은 제한하지 않지만, 다음 웨이브 예고에서 같은 약점이 반복될 수 있음을 보여줍니다.
- 재건으로 완전 길막, 보스 경로 차단, 스폰 적 고립을 만들 수 없습니다.

## 잔해 규칙

잔해는 구조물이 남긴 임시 전장 변화입니다.

기본값:

- 지속 시간: 8초
- 경로 비용 증가: 중간
- 적 이동 완전 차단 불가
- 보스 경로 차단 불가

잔해가 여러 개 겹치면 경로 비용은 증가하지만, 완전 차단은 되지 않습니다.

잔해가 경로를 막는 것처럼 보이면 시각 효과를 줄이고 경로 표시를 우선합니다.

## 상태이상 중첩 규칙

같은 상태이상은 짧은 시간 안에 반복 적용될수록 효과가 줄어듭니다.

상태이상은 적을 완전히 무력화하는 장치가 아니라, 방어선이 작동할 시간을 벌어주는 장치입니다.

### 상태이상 판정 6단계

1. 대상 등급을 확인합니다.

일반 적, 위험 적, 정예 적, 보스 부위, 보스 본체 중 하나로 분류합니다.

2. 기본 효과를 계산합니다.

카드, 구조물, 타일, 보스 부위 보상에서 제공하는 기본 수치와 지속 시간을 읽습니다.

3. 대상 저항을 적용합니다.

적 데이터의 `statusResistanceProfileId`와 현재 웨이브/보스 패턴의 임시 저항을 적용합니다.

4. 반복 감소를 적용합니다.

같은 상태이상이 짧은 시간 안에 반복됐으면 아래 반복 감소표를 적용합니다.

5. 충돌 우선순위를 적용합니다.

빙결 중 넉백, 도발 중 보스 강제 패턴처럼 동시에 성립하기 어려운 효과를 정리합니다.

6. 피드백을 표시합니다.

저항, 감소, 해소, 면역에 가까운 약화는 모두 작은 아이콘이나 짧은 문구로 보여줍니다.

기본 감소:

| 반복 횟수 | 효과 |
| ---: | ---: |
| 1회 | 100% |
| 2회 | 70% |
| 3회 | 45% |
| 4회 이상 | 25% |

감소는 5초 동안 유지된 뒤 초기화됩니다.

보스는 별도의 상태이상 저항을 먼저 적용하고, 그 다음 반복 감소를 적용합니다.

### 대상 등급별 목표 범위

| 대상 | 둔화 | 빙결 | 넉백 | 도발 |
| --- | --- | --- | --- | --- |
| 일반 적 | 30~60% 감속 | 0.5~1.5초 정지 | 1~3타일 후퇴 | 대부분 적용 |
| 위험 적 | 20~45% 감속 | 0.25~0.8초 정지 | 0.5~2타일 후퇴 | 일부 역할 저항 |
| 정예 적 | 10~35% 감속 | 0.1~0.4초 정지 | 0.25~1타일 후퇴 | 짧게 적용 또는 부분 적용 |
| 보스 부위 | 부위별 약화 | 정지 대신 부위 취약 | 부위 파괴 중 약한 밀림 | 특정 패턴에만 적용 |
| 보스 본체 | 5~20% 감속 | 정지 없음, 짧은 감속 | 대부분 강한 저항 | 강제 패턴보다 낮은 우선순위 |

이 표는 시작점입니다.

체감이 맞지 않으면 지속 시간보다 예고, 효과 피드백, 적 조합을 먼저 조정합니다.

### 침묵/방해 규칙

침묵은 플레이어의 입력을 막는 침묵이 아닙니다.

이 게임의 침묵은 마나, 드로우, 오라, 수리 효율처럼 전투 흐름을 흐리게 하는 방해 효과입니다.

침묵 금지선:

- 카드를 아예 사용하지 못하게 만들지 않습니다.
- 손패를 강제로 버리게 만들지 않습니다.
- 마나와 드로우를 동시에 완전히 봉쇄하지 않습니다.
- 영향 범위와 원인 적을 UI로 보여줍니다.

침묵은 우선 처치 질문이어야 합니다.

플레이어가 "저 적을 먼저 잡아야 한다"는 결론에 도달하면 성공입니다.

## 넉백 규칙

넉백은 적을 경로 뒤쪽으로 밀어냅니다.

예외:

- 보스는 대부분 넉백에 강하게 저항합니다.
- 기지에 거의 도달한 적은 넉백 거리가 줄어듭니다.
- 경로가 바뀐 직후 0.5초 동안은 넉백 방향을 기존 경로 기준으로 계산합니다.

넉백으로 적을 경로 밖에 영구 고립시킬 수 없습니다.

넉백 해소 규칙:

- 넉백 후 적은 항상 유효한 경로 위에 다시 놓입니다.
- 넉백으로 기지 도달 판정을 취소할 수는 있지만, 이미 발생한 기지 피해를 되돌리지는 않습니다.
- 같은 적이 3초 안에 넉백을 3회 이상 받으면 다음 넉백은 거리보다 짧은 경직으로 바뀝니다.
- 보스 부위 파괴 직후 2초 동안만 약한 보스 넉백 보정이 허용됩니다.

## 빙결 규칙

빙결은 일반 적을 짧게 정지시킵니다.

정예 적은 매우 짧게 정지합니다.

보스는 정지하지 않고 이동 속도가 잠시 감소합니다.

빙결 중인 적에게 넉백을 적용하면 빙결이 해제됩니다.

이 규칙은 적이 화면에서 부자연스럽게 멈춘 채 밀리는 상황을 줄이기 위한 것입니다.

빙결 해소 규칙:

- 빙결이 해제된 적은 1초 동안 같은 빙결의 2회차 반복 감소를 받습니다.
- 빙결은 적 공격 애니메이션을 끊을 수 있지만, 이미 확정된 구조물 피해는 취소하지 않습니다.
- 정예와 보스는 빙결 아이콘 대신 `빙결 약화` 아이콘을 표시합니다.
- 빙결 약화는 정지가 아니라 감속, 취약, 부위 노출 중 하나로 변환됩니다.

## 과부하 규칙

과부하는 일시적 성능 증가와 이후 대가를 함께 가집니다.

과부하 처리:

1. 즉시 버프 적용
2. 지속 시간 종료
3. 페널티 적용

과부하 중 구조물이 파괴되면 페널티는 적용하지 않습니다.

대신 파괴 이벤트는 정상 처리합니다.

과부하 페널티를 무효화하는 카드나 아티팩트는 한 번만 적용됩니다.

## 수리 규칙

수리는 구조물의 현재 체력을 회복합니다.

기본 제한:

- 최대 체력을 넘을 수 없습니다.
- 이미 파괴된 구조물은 수리할 수 없습니다.
- 자동 복구로 되살아난 구조물은 2초 동안 수리 효율이 감소합니다.

수리 우선순위:

1. 자동 복구
2. 즉발 수리 카드
3. 오라 기반 회복
4. 아티팩트 보정

땜장이의 수리는 구조물 파괴를 없애는 것이 아니라, 파괴 타이밍을 늦추는 역할입니다.

## 처치와 자원 규칙

적 사망 시:

1. 사망 위치 기록
2. 사망 효과 처리
3. 처치 기반 자원 계산
4. 처치 몰림 보정 적용
5. 모든 플레이어 게이지 충전
6. 드로우/마나 발동 확인

마지막 타격 보너스는 없습니다.

소환된 임시 적이 있다면 자원 지급량을 낮게 설정할 수 있습니다.

자원 파밍용 무한 소환을 막기 위한 규칙입니다.

### 처치 몰림 보정

처치 기반 자원은 시원해야 하지만, 웨이브 겹치기와 광역 콤보가 무한 마나처럼 느껴지면 안 됩니다.

짧은 시간 안에 처치가 몰리면 충전값을 아래처럼 보정합니다.

| 2초 내 처치 수 | 마나/드로우 충전 |
| ---: | ---: |
| 1~8마리 | 100% |
| 9~16마리 | 85% |
| 17~30마리 | 70% |
| 31마리 이상 | 55% |

보정은 처치 보상을 없애는 장치가 아니라, 폭발적인 순간 이후에도 전투 마나 한도가 의미 있게 남도록 하는 장치입니다.

보스 부위 파괴, 정예 처치, 이벤트 적 처치는 이 보정을 받지 않을 수 있습니다.

### 자원 지급 예외

자원은 다음 경우 줄어들거나 지급되지 않을 수 있습니다.

| 대상 | 처리 |
| --- | --- |
| 무한 소환 가능 적 | 낮은 충전값 |
| 튜토리얼용 허수 적 | 자원 지급 없음 |
| 보스가 소환한 일회성 탄막 개체 | 자원 지급 없음 |
| 정예가 만든 분신 | 낮은 충전값 |
| 플레이어가 직접 만든 훈련 표적 | 자원 지급 없음 |

누가 마지막 타격을 넣었는지는 자원 지급에 영향을 주지 않습니다.

모든 플레이어는 파티 처치 결과로 자기 게이지를 충전합니다.

## 드로우와 손패 한도

손패 한도를 넘는 드로우는 발생하지 않습니다.

드로우가 막힌 경우:

- 드로우 게이지는 유지됩니다.
- 손패 공간이 생기면 다음 드로우 체크 때 발동합니다.
- 카드가 소멸하지 않습니다.

손패 한도 초과가 자주 발생하면 UI에서 버리기를 유도합니다.

## 버리기 규칙

버리기는 웨이브당 1회입니다.

겹친 전투에서는 최대 3회까지 보유합니다.

버리기 처리:

1. 카드 선택
2. 버린 카드 더미로 이동
3. 소량 마나 지급
4. 버리기 횟수 감소

버리기로 얻는 마나는 전투 마나 한도를 넘지 않습니다.

버리기는 드로우가 아니라 손패 막힘 해소와 소량 회복 장치입니다.

### 버리기 횟수 생성과 소멸

버리기 횟수는 웨이브 단위로 생기지만, 겹친 전투에서는 한 전투 안에 압축되어 들어옵니다.

기본:

- 새 웨이브가 전투에 합류하면 버리기 횟수 1회를 추가합니다.
- 보유 가능한 버리기 횟수는 최대 3회입니다.
- 전투가 끝나면 남은 버리기 횟수는 사라집니다.
- 보상 선택 화면으로 버리기 횟수를 들고 갈 수 없습니다.

예시:

```text
현재 버리기 1회 보유
다음 웨이브 2개를 추가 호출
-> 버리기 2회 추가
-> 총 3회 보유
```

버리기 횟수는 손패 정비권이지 보상 증가가 아닙니다.

버리기로 얻는 마나는 카드 1장을 억지로 순환시키는 최소 보상에 가깝게 유지합니다.

## 웨이브 겹치기 규칙

기본:

- 최대 3개까지 겹칠 수 있습니다.
- 아티팩트로만 최대치를 늘릴 수 있습니다.
- 보상 총량은 증가하지 않습니다.
- 희귀도 보정은 없습니다.
- 카드 선택지 증가도 없습니다.

겹치기 처리:

1. 플레이어가 호출 제안
2. 투표 조건 확인
3. 겹침 한도 확인
4. 다음 웨이브 스폰 예약 제거
5. 즉시 현재 전투에 추가
6. UI에 현재 겹침 수 표시

### 투표 예외

투표는 8초 동안 유지됩니다.

예외 처리:

| 상황 | 처리 |
| --- | --- |
| 전투가 투표 중 종료됨 | 투표 취소 |
| 제안자가 나감 | 남은 플레이어 기준으로 투표 유지 |
| 같은 웨이브 호출 제안 중복 | 기존 투표 UI에 합침 |
| 기지 체력이 투표 중 30% 이하로 하락 | 전원 동의 조건으로 즉시 전환 |
| 다음 웨이브 데이터 로딩 실패 | 투표 취소, 재시도 가능 |
| 이미 겹침 한도 도달 | 버튼 비활성화와 이유 표시 |

투표 실패는 페널티가 없습니다.

웨이브 겹치기 제안 자체가 자원이나 쿨다운을 소모하지 않습니다.

### 호출 불가 조건

아래 상황에서는 다음 웨이브 호출을 막습니다.

- 튜토리얼의 첫 설치 학습 중
- 보상 선택 화면
- 상점 화면
- 패배 연출이 시작된 뒤
- 다음 웨이브 데이터가 아직 확정되지 않은 상태
- 기본 한도 3개를 넘는 호출, 단 아티팩트 효과가 있으면 그 효과 범위 안에서 허용

MVP에서는 일반 웨이브 중 다음 보스일을 직접 앞당겨 호출하지 않습니다.

보스전이 시작된 뒤에는 일반 웨이브를 추가 호출할 수 있습니다.

기지 체력 30% 이하:

- 전원 동의 필요
- 투표 UI가 위험 상태로 표시

보스전:

- 보스전 중에도 호출 가능
- 보상 증가 없음
- 일반 웨이브가 보스와 동시에 들어올 수 있음

## 튜토리얼과 첫 세션 처리 규칙

튜토리얼은 별도 규칙 게임이 아니라, 실제 런의 규칙을 안전한 크기로 보여주는 모드입니다.

처리 원칙:

1. 한 튜토리얼 장면은 하나의 `teachesTags` 묶음만 강하게 보여줍니다.
2. 튜토리얼에서 길막, 구조물 파괴, 웨이브 겹치기, 보스 부위는 실제 시스템 판정을 사용합니다.
3. 튜토리얼용 허수 적은 자원 지급이 없을 수 있지만, 실제 첫 세션 적은 처치 기반 마나와 드로우를 정상 지급합니다.
4. 자동 시연은 제안만 하고, 마지막 성공 입력은 플레이어가 직접 해야 합니다.
5. 스킵한 플레이어도 첫 10일 체크포인트 힌트는 받을 수 있습니다.

첫 세션 제한:

- 1~2일에는 한 방향 압박만 사용합니다.
- 1~4일에는 모든 인원수에서 실제 스폰 방향을 1개로 제한합니다.
- 1인은 1~10일 동안 동쪽 외 일반 웨이브를 사용하지 않습니다.
- 7일과 9일만 2인 이상에서 약한 2방향 압박을 사용할 수 있습니다.
- 새 적 등장일에는 강한 다방향 압박을 함께 사용하지 않습니다.
- 5일 첫 상점은 5~6개 항목만 보여줍니다.
- 8일 웨이브 겹치기는 보상, 희귀도, 선택지 문구 없이 템포 선택으로만 표시합니다.
- 10일 첫 보스는 3방향 이상 동시 압박을 만들지 않습니다.
- 첫 10일 패배 화면은 플레이어 책임보다 되돌아갈 튜토리얼 장면을 먼저 제안합니다.

첫 10일 웨이브는 `learningPhaseIndex`를 기준으로 패배 분석, 보상 프로필, 힌트 문구를 연결합니다.

이 값은 난이도를 낮추는 보정값이 아니라, 플레이어가 어떤 판단을 아직 이해하지 못했는지 찾기 위한 태그입니다.

### 11~20일 첫 운영 규칙

11~20일은 첫 보스 후 고른 아티팩트와 상점 선택을 검증하는 첫 운영 구간입니다.

이 구간은 `chapterLoopId: spring2_operation_loop_011_020`과 `chapterPhaseIndex`를 기준으로 패배 분석, 작은 상점 추천, 20일 변형 보스 선택을 연결합니다.

처리 규칙:

- 11~20일은 선택을 즉시 처벌하지 않고, 15일 작은 상점과 20일 변형 보스에서 다시 조정할 기회를 줍니다.
- 1인은 11~20일에도 동쪽 외 일반 웨이브를 사용하지 않습니다.
- 2인은 북쪽과 동쪽만 사용하고, 3방향 이상 동시 압박을 만들지 않습니다.
- 3인은 서쪽/북쪽/동쪽만 사용하고, 남쪽 일반 웨이브를 만들지 않습니다.
- 4인은 남쪽을 낮은 위험 보조 압박으로만 사용할 수 있으며, 사방 동시 압박은 아직 사용하지 않습니다.

| 맡음 표시한 플레이어가 나감 | 맡음 표시 제거 |
| 전투가 종료됨 | 전투 핑은 접고, 리포트에 필요한 태그만 기록 |
| 같은 위치에 핑이 몰림 | 하나의 묶음으로 접고 체크 수를 표시 |
| 치명 경고와 일반 핑이 겹침 | 치명 경고를 우선 표시하고 일반 핑은 흐리게 표시 |

핑은 플레이어 책임 추적용 기록이 아닙니다.

텔레메트리에서는 어떤 협동 요청이 읽히고 해소됐는지만 봅니다.

## 보상 정산 규칙

겹친 웨이브가 여러 개일 때:

- 각 웨이브의 기본 보상을 순서대로 정산합니다.
- 보상 수량은 원래 웨이브 수와 같습니다.
- 추가 배율은 없습니다.

예시:

```text
2일 웨이브와 3일 웨이브를 겹쳐 클리어
-> 2일 기본 보상 선택
-> 3일 기본 보상 선택
```

플레이어가 보상을 한 번에 몰아서 받는 것처럼 보이지 않게, UI는 "밀린 보상 처리"가 아니라 "각 웨이브 정산"으로 표시합니다.

보상 선택 중 플레이어가 나가면 해당 플레이어의 선택은 자동 보류됩니다.

멀티에서는 모든 플레이어가 선택을 끝내거나 제한 시간이 끝나야 다음 하루로 넘어갑니다.

제한 시간이 끝나면 기본값은 `건너뛰기`가 아니라, 가장 안전한 보상 후보 1장을 임시 선택으로 둡니다.

플레이어가 재접속하면 다음 상점 전까지 그 선택을 한 번 되돌릴 수 있습니다.

### 첫 10일 카드 보상 프로필 규칙

첫 10일 보상 프로필은 후보를 고르는 필터이지 보상 강화가 아닙니다.

처리 순서:

1. 완료한 일자의 기본 보상 횟수를 확인합니다.
2. 해당 일자의 첫 10일 보상 프로필을 읽습니다.
3. 플레이어 직업, 최근 전투 문제 태그, 현재 덱 태그를 참고해 후보 풀을 필터링합니다.
4. 카드 후보 3장을 제시합니다.
5. 카드 1장 선택 또는 골드 거절을 처리합니다.

금지:

- 후보 수 4장 이상 증가
- 웨이브 겹치기 횟수에 따른 희귀도 증가
- 클리어 시간에 따른 보상 후보 강화
- 처치 수에 따른 카드 후보 수 증가
- 직업 약점을 완전히 지우는 공용 카드 우선 노출
- 첫 10일 일반 보상에서 강제 저주 삽입

같은 역할 태그 카드가 3장 모두 나오면 후보를 다시 뽑습니다.

다시 뽑아도 조건을 만족하지 못하면 직업 기본 보강 카드 1장, 공용 약한 보완 카드 1장, 골드 선택을 우선 표시합니다.

## 보스 후 성장 처리 순서

보스 처치 후에는 아래 순서를 고정합니다.

```text
보스 처치
-> 자동 저장
-> 보스 결과 요약
-> 개인 보스 카드 보상
-> 아티팩트 선택
-> 챕터 상점
-> 다음 일자 예고
-> 자동 저장
```

10일 첫 보스 기본 정산:

- 파티 골드 +35
- 보스 파편 +1
- 아티팩트 후보 3개
- 개인 카드 보상 1회
- 추가 보상 배율 없음

보스 부위 파괴는 추가 파편을 주지 않습니다.

부위 파괴 효과는 전투 중 패턴 약화, 이동 속도 감소, 카드 드로우로 처리합니다.

## 첫 보스 처리 규칙

침묵의 거상은 10일 테스트 런의 첫 결산이므로, 규칙보다 읽힘을 우선합니다.

전투 단계:

1. 입장 예고
2. 다리부 학습
3. 짓누르기 선택
4. 등불부 선택
5. 마지막 접근
6. 결과 연결

처리 규칙:

- 첫 보스 단계 계획은 `boss_phase_plan_silent_colossus_010`을 사용합니다.
- 첫 추천 부위는 다리부지만, 본체 공격을 금지하거나 실패 처리하지 않습니다.
- 본체만 오래 공격하면 결과 태그에서 `boss_legs_ignored`를 우선 고려합니다.
- 전면부가 파괴되어도 짓누르기 패턴은 삭제되지 않고 약화됩니다.
- 다리부가 파괴되어도 보스는 완전히 정지하지 않고 이동 속도만 감소합니다.
- 등불부가 파괴되면 모든 플레이어가 카드 1장을 뽑지만, 추가 카드 보상 후보를 만들지 않습니다.
- 부위 파괴 중 진행 중인 패턴은 즉시 취소보다 다음 반복부터 약화 적용을 기본으로 합니다.
- 예고된 구조물이 이미 사라졌다면 가장 가까운 합법 구조물을 다시 고르되, 재표식 시간을 1초 이상 줍니다.
- 첫 보스 동반 웨이브는 `boss_companion_policy_silent_colossus_010`을 따릅니다.
- 1인은 동쪽만 사용하고, 모든 인원수에서 3방향 이상 동시 보스 압박을 만들지 않습니다.
- 첫 보스 동반 웨이브는 새 적 학습, 추가 보상, 희귀도 증가를 담당하지 않습니다.

보스 후 상점에서는 파티 자원 구매를 최대 2회로 제한합니다.

이 제한은 메뉴 피로를 줄이고, 다음 상점까지 선택의 여운을 남기기 위한 장치입니다.

## 아티팩트 슬롯 규칙

기본 슬롯은 3개입니다.

슬롯이 가득 찬 상태에서 새 아티팩트를 얻으면:

1. 새 아티팩트 후보 표시
2. 기존 장착 아티팩트 표시
3. 교체할지 포기할지 선택

멀티에서는 아티팩트 장착과 교체에 투표가 필요합니다.

아티팩트 슬롯 +1 효과는 최대 4개까지만 허용합니다.

첫 보스 기본 후보 풀에서는 `artifact_unstable_clock`을 제외합니다.

이 아티팩트는 웨이브 겹치기 최대치 이해가 충분해진 20일 이후 또는 별도 테스트에서 노출합니다.

### 아티팩트 선택 처리

아티팩트 선택은 파티 공유 결정이므로 항상 VoteSystem을 사용합니다.

처리 순서:

1. 보스 결과와 다음 10일 압박 태그를 확정합니다.
2. 아티팩트 후보 3개와 현재 장착 아티팩트를 함께 표시합니다.
3. 후보별 운영 축, 대가, 다음 압박 연결 태그를 표시합니다.
4. 빈 슬롯이 있으면 후보 1개를 장착 대상으로 투표합니다.
5. 슬롯이 가득 찼으면 후보 1개 선택 후 교체 대상 또는 `현재 유지`를 투표합니다.
6. 결과를 적용하고 `artifact_choice_resolved`와 `artifact_replacement_resolved`를 기록합니다.

시간 초과 처리:

- 빈 슬롯이 있고 득표 후보가 있으면 현재 최다 득표 후보를 임시 장착합니다.
- 슬롯이 가득 찼고 교체 합의가 없으면 현재 상태를 유지합니다.
- 무작위 교체를 하지 않습니다.
- 시간 초과로 장착된 임시 선택은 이어지는 상점 종료 전까지 한 번 재투표할 수 있습니다.

교체 제한:

- 기본 슬롯은 3개입니다.
- 슬롯 증가 효과를 받아도 최대 4개를 넘을 수 없습니다.
- 슬롯 증가 아티팩트는 강한 파워 누적이 아니라 교체 압박을 한 번 늦추는 효과로 취급합니다.
- 91일 이후 후보 풀은 새 아키타입 시작보다 기존 빌드 마무리를 우선합니다.
- 아티팩트는 웨이브 겹치기 보상, 카드 희귀도, 카드 후보 수를 증가시킬 수 없습니다.
- 아티팩트는 비활성 방향을 적 스폰이나 필수 방어 압박으로 열 수 없습니다.

### 정비 세션 처리

정비 세션은 전투 결과와 다음 압박을 연결하는 짧은 의사결정 구간입니다.

처리 순서:

1. 전투 요약과 피해 진단 태그를 확정합니다.
2. 개인 카드 보상 또는 거절을 처리합니다.
3. 다음 3~5일 주요 압박을 표시합니다.
4. 상점 항목을 피해 진단과 다음 압박에 맞춰 정렬합니다.
5. 파티 자원 투표를 한 번에 하나씩만 엽니다.
6. 상점 종료 후 다음 일자 예고와 자동 저장을 진행합니다.

정비 세션 제한:

- 일반 상점은 60~90초를 목표로 합니다.
- 보스 후 상점은 90~120초를 목표로 합니다.
- 시간 종료 시 강제 구매하지 않습니다.
- 구매 없이 넘어가는 것도 정상 선택입니다.
- 파티 자원 구매 투표는 동시에 1개만 열 수 있습니다.
- 보스 후 상점의 파티 자원 구매는 최대 2회입니다.

상점 추천은 정답이 아니라 정렬 기준입니다.

추천 항목을 구매하지 않아도 페널티는 없습니다.

## 이벤트 처리 규칙

전투 사이 이벤트는 짧은 선택 구간입니다.

상점처럼 많은 항목을 비교하는 화면이 아니라, 현재 런 상태와 다음 압박을 연결하는 2~3개의 딜레마입니다.

처리 순서:

1. 이벤트 등장 조건과 트리거 태그를 확정합니다.
2. 선택지 2~3개와 각 선택의 즉시 비용, 다음 영향, 소유권을 표시합니다.
3. 개인 선택은 해당 플레이어가 확정합니다.
4. 파티 자원, 기지 체력, 아티팩트, 다음 웨이브 압박을 바꾸는 선택은 투표로 처리합니다.
5. 결과를 적용하고 `event_choice_resolved`를 기록합니다.
6. 다음 웨이브 예고, 상점 추천, 전투 리포트에 결과 태그를 연결합니다.

이벤트 제한:

- 일반 이벤트는 30~60초를 목표로 합니다.
- 계절 전환이나 보스 직전 이벤트만 60~90초를 허용합니다.
- 선택지는 최소 2개, 최대 3개입니다.
- 3개 선택지는 보스, 계절 전환, 튜토리얼 이후 첫 특수 이벤트에만 우선 사용합니다.
- 시간 종료 시 무작위 선택을 하지 않습니다.
- 기본 시간 초과 선택은 상태 보존 또는 지나가기입니다.

이벤트 금지:

- 이벤트는 웨이브 겹치기 보상, 카드 희귀도, 카드 후보 수를 늘리지 않습니다.
- 이벤트는 비활성 방향을 적 스폰이나 필수 방어 압박으로 열지 않습니다.
- 저주 카드는 플레이어가 선택한 결과로만 들어갑니다.
- 선택지에 표시하지 않은 숨은 패널티를 적용하지 않습니다.
- 파티 투표를 동시에 2개 이상 열지 않습니다.

이벤트가 다음 웨이브를 바꾸는 경우:

1. 변경 대상은 이미 활성화된 방향 안에서만 고릅니다.
2. `WaveSpawnPlan`이 생성되기 전이면 후보 태그만 남깁니다.
3. `WaveSpawnPlan`이 이미 생성된 뒤라면 변경 가능한 필드만 수정하고 예고 UI를 즉시 갱신합니다.
4. 실제 스폰 방향과 예고 방향이 달라지면 이벤트 선택을 되돌리거나 예고를 다시 띄웁니다.

91~100일은 새 시스템을 여는 구간이 아니라 기존 판단을 최종 순서로 다시 묻는 구간입니다.

- 91일 이후 카드와 아티팩트 후보 풀은 새 아키타입 시작보다 기존 빌드 마무리를 우선합니다.
- 95일 상점은 모든 약점을 해결하는 만능 구매를 제공하지 않습니다.
- 99일과 100일에는 튜토리얼성 새 규칙 설명을 넣지 않습니다.
- 장기 압력 권역은 설치 권역 압박이며 경로 타일을 막지 않습니다.
- 장기 압력 권역, 동반 웨이브, 정예 압박은 비활성 방향에 생성되지 않습니다.
- 최종 보스는 모든 압박을 한 순간에 최대 강도로 겹치지 않습니다.

## 100일 결과 정산 규칙

100일 결과 화면은 승리와 패배 모두 `final_result_reflection_loop_6step`을 사용합니다.

처리 순서:

1. 결과를 확정하고 `final_result_reflection_started`를 기록합니다.
2. 마지막 킬존 위치, 최종 방어선 이전 횟수, 오래 버틴 구조물을 요약합니다.
3. 95일에 포기한 약점과 마지막 상점 선택을 회수합니다.
4. 결정적 장면 카드를 최대 3장까지 만듭니다.
5. 다음 런에서 바꿔볼 운영 제안을 최대 2개까지 만듭니다.
6. 파티 기록 저장 시 `party_chronicle_saved`를 기록합니다.

결과 정산 제한:

- 개인 딜량 순위, 처치 순위, 개인 실수 소유자 필드를 만들지 않습니다.
- 결정적 장면 카드는 방향, 구조물, 위험 태그, 보스 단계처럼 전장 사건만 사용합니다.
- 웨이브 겹치기 사용량은 보상 효율이나 추가 보상으로 환산하지 않습니다.
- 다음 런 제안은 정답 빌드, 필수 직업, 특정 카드 강요처럼 보이면 안 됩니다.
- 패배 결과도 플레이어 책임보다 전장 원인과 다음 시도 제안을 먼저 보여줍니다.

## 런 이후 메타 진행 규칙

런 이후 메타 진행은 `post_run_meta_loop_6step`을 사용합니다.

처리 순서:

1. 런 기록을 수집하고 `post_run_meta_progression_started`를 기록합니다.
2. 반복 실패 원인, 포기한 약점, 자주 쓴 대응을 학습 태그로 정리합니다.
3. 적 도감, 보스 기록, 훈련 장면처럼 정보성 해금을 먼저 처리합니다.
4. 새 카드 풀, 아티팩트 풀, 외형 후보를 역할 태그 기준으로 해금합니다.
5. 다음 런 준비 제안을 최대 2개까지 만듭니다.
6. 프로필 해금 상태와 파티 연대기를 저장합니다.

메타 진행 제한:

- 영구 공격력, 구조물 체력, 마나 회복량, 웨이브 보상 배율을 직접 올리지 않습니다.
- 딜량, 처치 수, 웨이브 겹치기 횟수, 개인 실수 태그는 메타 해금량 증가 조건으로 쓰지 않습니다.
- 카드/아티팩트 해금은 보상 후보 풀을 넓히는 것이지 후보 수나 희귀도를 올리는 효과가 아닙니다.
- 다음 런 준비 제안은 직업, 카드, 아티팩트를 강제하지 않습니다.
- 외형 보상은 전투 수치와 보상 확률에 영향을 주지 않습니다.
- 숙련 플레이어는 메타 해금 없이도 클리어할 수 있어야 합니다.

## 도감/훈련장 재방문 규칙

도감과 훈련장은 `knowledge_revisit_loop_6step`을 사용합니다.

처리 순서:

1. 재방문 이유를 표시하고 `knowledge_revisit_started`를 기록합니다.
2. 볼 대상을 하나 선택합니다.
3. 짧은 도감 카드를 표시하고 `encyclopedia_entry_viewed`를 기록합니다.
4. 연결된 훈련 장면이 있으면 `training_scenario_started`를 기록합니다.
5. 훈련 종료 시 사용 대응 태그와 제안 대응 태그를 `training_scenario_completed`로 기록합니다.
6. 다음 런 제안이나 즐겨찾기로 연결하면 `knowledge_revisit_to_run_linked`를 기록합니다.

재방문 제한:

- 재방문은 필수가 아니며 완료하지 않아도 런 시작, 난이도, 보상 확률이 바뀌지 않습니다.
- 훈련 장면은 하나의 학습 태그만 다룹니다.
- 훈련 장면은 실제 골드, 카드, 아티팩트, 메타 파워를 지급하지 않습니다.
- 훈련 장면은 비활성 방향 스폰이나 필수 방어 압박을 만들지 않습니다.
- 도감 카드는 정답 빌드, 필수 직업, 강제 카드 추천을 표시하지 않습니다.
- 대응 비교는 점수, 등급, 개인 평가가 아니라 대응 태그 차이만 보여줍니다.

## 보스 기지 도달 규칙

MVP 기준:

1. 보스가 기지에 도달합니다.
2. 기지 체력 15 피해를 줍니다.
3. 5초 예고가 시작됩니다.
4. 5초 안에 밀어내거나 처치하지 못하면 즉시 패배합니다.

이 규칙은 첫 보스 기준입니다.

최종 보스는 별도 규칙을 가질 수 있지만, 예고 없는 즉시 패배는 피합니다.

## 패배와 복구 규칙

패배는 납득 가능해야 합니다.

패배 조건:

- 기지 체력 0
- 보스 기지 도달 후 즉시 패배 예고 실패
- 특정 특수 모드의 별도 조건 실패

패배 직전 1초 동안은 핵심 경고를 우선 표시합니다.

단, 이 시간은 추가 조작 기회를 보장하는 무적 시간이 아닙니다.

패배 화면에는 최소한 아래 정보를 보여줍니다.

- 마지막으로 기지에 피해를 준 적
- 가장 많이 뚫린 방향
- 가장 많이 파괴된 구조물 종류
- 웨이브 겹치기 이후 위험도가 급상승한 시점
- 손패가 막힌 시간

이 정보는 플레이어를 탓하기 위한 것이 아니라 다음 판의 토론 재료입니다.

### 예고와 실제 전투 불일치

예고 UI는 이미 확정된 `WaveSpawnPlan`을 설명해야 합니다.

UI가 표시한 방향과 실제 스폰 방향이 다르면 전투 판정이 맞더라도 플레이어는 억울하게 느낍니다.

불일치 방지 규칙:

1. 예고 UI는 `WaveSpawnPlan.directions`만 위험 방향으로 표시합니다.
2. 비활성 방향은 위험 방향, 추천 방어 방향, 겹치기 위험 방향으로 표시하지 않습니다.
3. 예고 생성 후 스폰 계획이 바뀌면 예고 UI를 즉시 갱신하고 짧은 변경 표시를 남깁니다.
4. 갱신할 수 없다면 기존 예고와 충돌하는 스폰을 취소하거나 약화합니다.
5. 보스가 예고를 흐리게 만드는 패턴도 후보 방향을 활성 방향 안에서만 보여줍니다.

패배 원인 판정 순서:

1. 마지막 기지 피해 원인을 확인합니다.
2. 마지막 10초 동안 반복된 방향 피해를 확인합니다.
3. 구조물 연쇄 붕괴가 먼저 있었는지 확인합니다.
4. 손패 막힘과 드로우 손실이 있었는지 확인합니다.
5. 웨이브 겹치기 후 20초 안에 위험이 급증했는지 확인합니다.
6. 그래도 설명이 약하면 `정보 전달 실패`로 분류합니다.

`정보 전달 실패`는 플레이어 실수가 아니라 UI와 웨이브 설계의 수정 신호입니다.

## 저장 규칙

자동 저장 시점:

- 하루 시작
- 보스 처치 후
- 상점 진입
- 아티팩트 선택 완료

전투 중 저장은 MVP에서 제외합니다.

전투 중 저장을 지원하면 경로, 투사체, 상태이상, 웨이브 겹침 상태를 모두 저장해야 하므로 위험합니다.

## 중단/저장/재개 규칙

중단과 재개는 `session_resume_loop_6step`으로 처리합니다.

1. 안정 저장점이 생기면 `session_savepoint_created`를 기록합니다.
2. 연결 끊김, 입력 없음, 호스트 응답 지연을 감지하면 `session_interrupt_detected`를 기록합니다.
3. 해당 플레이어의 직업을 보류 모드로 전환하고 `player_role_reserved`를 기록합니다.
4. 재접속한 플레이어에게 현재 전투/상점/투표 스냅샷을 전달하고 `resume_snapshot_delivered`를 기록합니다.
5. 2분을 넘긴 장기 이탈은 다음 안정 저장점까지 보류 모드로 유지하고 `long_absence_resolved`를 기록합니다.
6. 같은 플레이어가 같은 직업을 이어받으면 `session_resume_confirmed`를 기록합니다.

보류 모드 규칙:

- 기존 구조물은 계속 작동합니다.
- 해당 직업의 손패, 마나, 버리기 횟수는 잠급니다.
- AI는 MVP에서 카드를 대신 사용하지 않습니다.
- 남은 플레이어는 이탈자의 개인 카드를 사용할 수 없습니다.
- 남은 플레이어는 파티 공유 행동만 정상적으로 계속할 수 있습니다.

재개 금지선:

- 현재 접속 인원으로 `playerCountAtStart`, `activeDirections`, `scalingProfileId`를 다시 계산하지 않습니다.
- 이탈 또는 재접속을 보상, 골드, 카드 후보 수, 희귀도 보정으로 환산하지 않습니다.
- 재개 과정에서 상점, 카드 보상, 아티팩트 선택을 새로 뽑지 않습니다.
- 진행 중 투표에 복귀하면 남은 시간으로만 합류합니다.
- 비활성 방향을 위험 방향이나 보상 방향처럼 다시 표시하지 않습니다.

## 멀티플레이 동기화 규칙

멀티플레이에서는 호스트 또는 서버가 최종 판정을 가집니다.

클라이언트는 먼저 미리보기를 보여줄 수 있지만, 실제 자원 사용과 구조물 설치는 확정 응답을 받은 뒤 고정합니다.

동기화 대상:

- 기지 체력
- 현재 일자와 계절
- 활성 웨이브 목록
- 적 위치와 주요 상태
- 구조물 위치, 체력, 소유자
- 카드 사용 결과
- 마나와 드로우 게이지
- 버리기 횟수
- 아티팩트 장착 상태

재접속 시:

1. 현재 전투 상태를 받습니다.
2. 손패와 자원 상태를 복구합니다.
3. 내 구조물 소유권을 복구합니다.
4. 진행 중 투표가 있으면 현재 남은 시간으로 합류합니다.

연결이 끊긴 플레이어의 구조물은 유지됩니다.

해당 플레이어의 카드는 자동 사용하지 않습니다.

MVP에서는 끊긴 플레이어의 조작을 AI가 대신하지 않습니다.

## 무한 루프 방지

효과가 서로를 계속 발동시키는 상황은 강제로 끊습니다.

제한:

- 한 프레임 안에 같은 카드가 같은 대상을 다시 발동할 수 없습니다.
- 같은 구조물의 파괴 직전 효과는 10초 안에 1회만 발동합니다.
- 한 적이 1초 안에 같은 상태이상을 4회 이상 받으면 추가 적용을 무시할 수 있습니다.
- 한 전투에서 같은 아티팩트가 만든 무료 카드 생성은 상한을 둡니다.
- 버리기로 얻은 마나로 같은 카드를 무한히 되사는 구조는 금지합니다.

루프가 감지되면 게임을 멈추지 않고, 초과 발동만 무시합니다.

개발 로그에는 어떤 효과가 막혔는지 남깁니다.

## 규칙 변경 금지선

아래 규칙은 프로토타입 중에도 쉽게 바꾸지 않습니다.

- 시간 경과 마나 자동 회복 없음
- 완전 길막 없음
- 웨이브 겹치기 보상 증가 없음
- 마지막 타격 보너스 없음
- 구조물 파괴는 전술 자원이어야 함

이 금지선을 바꾸려면 README의 핵심 설계 원칙부터 다시 검토해야 합니다.
